# 灵矽协议技术验证报告

验证日期：2026-10-24。脚本：`bridge/scripts/spike.ts`（`pnpm --filter bridge spike ...`）。
环境：macOS 26.0.1，Node 24，设备通过 OTA 激活并绑定到一个开启「统一意图识别」的智能体。

## 结论速览

| 验证项 | 结果 | 对方案的影响 |
|---|---|---|
| WebSocket 握手（`ws` 库带自定义请求头） | 通过，约 0.3 秒 | 连接由桥接服务持有（方案 A） |
| 设备端 MCP：`initialize` / `tools/list` | 握手后立即下发，工具列表被接受 | 无需公网地址，无需在控制台关联 MCP |
| `listen.detect` + `text` 当作用户输入 | 通过：服务端回 `stt` 并按普通对话处理 | 网页上可提供文字输入兜底，演示时识别出错也能继续 |
| 语音触发工具调用 | 通过：文字或语音输入后约 1.5 秒收到 `tools/call`，`instruction` 被大模型整理成完整指令 | F1 成立 |
| PCM 上行 | 通过：上传 2.7 秒 16kHz PCM，`listen stop` 后 0.9 秒返回 `stt` | 浏览器只需采集 PCM，不用 Opus 编码 |
| 下行音频格式 | hello 声明 PCM 时，服务端回 `format: pcm, 16000Hz`，二进制帧全是 640 字节（20ms） | **与文档写的「下行固定 Opus」不一致**，实际不需要任何 Opus 编解码 |
| 工具调用超时 | 延迟 10 秒返回：正常播报结果；延迟 30 秒返回：服务端在我们回复后又发来一次相同的 `tools/call` | 超时在 10–30 秒之间；`run_task` 必须立即返回，并对重复调用去重 |
| `text_response` 主动播报 | 通过：内容被原样念出（不经大模型改写），发出后约 0.6 秒开始播放 | F3 用它播报任务摘要 |
| 空闲断连 | 空闲 120 秒时服务端发 `goodbye`，播一句告别语，然后断开连接 | 桥接服务要自动重连，并丢弃 `goodbye` 之后的告别语音 |

## 关键观测记录

### 工具调用超时（延迟 30 秒）

```
[4.41s]  ← tools/call id=3 self.coding.run_task
[34.41s] → result id=3
[36.74s] ← tools/call id=4 self.coding.run_task（参数与 id=3 完全相同）
```

服务端在等待期间已判定超时，大模型随后重试。若 `run_task` 同步执行 Claude Code，会重复启动任务。

### 工具结果会被大模型当作事实复述

模拟返回「任务已完成」时，播报内容是「已经帮你建好了 hello.txt」。真实实现里 `run_task` 的返回文字必须明确写「已开始执行，完成后会主动播报」，否则大模型会提前宣布完成。

### 空闲断连

```
[0.34s]   ← hello
[120.36s] ← goodbye
[121.52s] ← tts start / sentence_start「时间过得真快，」
[126.57s] 连接关闭 1006
```

## 方案调整

1. **去掉 Opus**：上下行都用 16kHz 单声道 PCM、20ms 一帧。不再需要 `opusscript`。
2. **`self.coding.run_task` 立即返回**：返回「已开始执行，完成后会主动语音通知」；同一时间只跑一个任务，相同指令在任务进行中重复到达时直接返回「已在执行」。
3. **完成播报**：任务结束后发 `listen.detect`，`text_response` 放摘要；当时若连接已断，先重连再发。
4. **连接保活**：服务端关闭连接后立即重连（失败时退避重试）；收到 `goodbye` 后到下一次 `tts stop` 之间的音频不转发给网页。
5. **控制台建议**：智能体「对话与视觉」里把空闲超时调长，减少断连次数（重连仍是兜底）。
